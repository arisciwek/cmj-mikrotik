## A. Ringkasan Eksekutif

Server VPS ini (`cmj.ciptamasjaya.co.id`) menjalankan WireGuard dalam mode **userspace** (`wireguard-go`), bukan kernel module, karena kernel OpenVZ/Virtuozzo (`5.4.0-1160`) tidak mendukung modul kernel WG.

Interface yang **sedang jalan (live)** adalah `wg0` dengan IP `10.100.0.1/24`, listen port UDP `48231`, dan saat ini **hanya memuat 1 peer**:

- Router kantor (MikroTik) di `103.18.34.192:48231`
- allowed-ips live: `10.100.0.2/32, 192.168.18.0/24`

File konfigurasi `/etc/wireguard/wg0.conf` sebenarnya berisi **27 peer** (1 MikroTik + 26 user bernama + 1 LXC Carbonio), **tetapi 26 peer tersebut TIDAK AKTIF / tidak dimuat** ke interface yang berjalan. Akibatnya: hanya tunnel site-to-site ke kantor yang bekerja; VPN user individu via VPS ini tidak aktif saat ini.

Terdapat pula masalah operational: script startup utama (`/usr/local/bin/wireguard-up-all.sh`) **sudah hilang**, padahal unit systemd `wireguard-up.service` mengarah ke file tersebut. Artinya pada reboot berikutnya tunnel akan **GAGAL** naik (script tidak ditemukan).

## J. Temuan & Anomali (untuk ditindaklanjuti engineer)

### [1] Peer Tidak Konsisten (KRITIS)
`wg0.conf` punya 27 peer, tapi live hanya 1 (MikroTik). 26 user + LXC Carbonio **tidak bisa connect** ke VPS ini saat ini.
**Penyebab akar:** bug `wireguard-go` userspace pada `wg setconf` (hanya peer pertama yang ke-load / timeout). Solusi di `cmj-final.sh` hanya memuat 1 peer → menghilangkan user peers.

### [2] Startup Fragil (KRITIS)
`wireguard-up.service` → script `/usr/local/bin/wireguard-up-all.sh` **HILANG**. Pada reboot: unit gagal, dan `cmj-final` DISABLED → tunnel **MATI total**. Butuh: script hidup + enable unit yang benar, atau satukan logika.

### [3] Subnet Kantor `192.168.10.0/24` Tidak Terjangkau
Live allowed-ips MikroTik = hanya `192.168.18.0/24` (bukan `192.168.10`). Route `192.168.10.0/24` juga tidak ada. VPS tidak bisa akses LAN #2.

### [4] Keamanan: File Rahasia World-Readable (TINGGI)
```
/etc/wireguard/wg0.conf          = 644  (isi 26 PresharedKey + PrivateKey)
/etc/wireguard/wg0.conf.bak-*    = 644  (sama)
/etc/wireguard/privatekey        = 644  (PrivateKey VPS)
/etc/wireguard/wg0.private       = 644  (sama, duplikat)
```
Ada banyak user non-root lokal (`cmj`, `app`, `dms`, `sales`, `crm`, dll) yang **bisa membaca semua kunci** tersebut.
**Rekomendasi:** `chmod 600`, milik root, dan pindah backup ke direktori aman.

### [5] Daemon Orphan
PID 148518 PPID 1 — tidak dilacak systemd; kalau daemon crash/restart tidak otomatis naik kembali (`Restart=` tidak berlaku karena di-fork).

### [6] Duplikasi Key & Konfig
`privatekey == wg0.private` (identik). Banyak file `.bak` (5 buah) dengan jumlah peer berbeda (26/26/1/26/27) → riwayat trial-error, rawan kebingungan & kebocoran (lihat [4]).

## K. Kesimpulan

Tunnel saat ini **HANYA** berfungsi sebagai site-to-site **VPS ↔ kantor** (MikroTik `103.18.34.192`). VPN user individu (26 peer) terdefinisi di file tapi tidak jalan karena keterbatasan `wireguard-go` userspace + pendekatan UAPI yang hanya memuat 1 peer. Konfigurasi startup rapuh (script hilang) sehingga tidak tahan reboot. Ada isu keamanan izin file kunci yang perlu diperbaiki.

> Semua temuan didasarkan pada bacaan read-only (`wg show`, `systemctl`, file config, `iptables`, proses). Tidak ada perubahan yang dilakukan.

## L. Petunjuk untuk Engineer (yang akan memperbaiki)

- Cek ulang apakah user VPN seharusnya connect ke VPS ini atau ke MikroTik di kantor (bisa jadi desain awalnya user → kantor, VPS hanya hub).
- Jika user harus lewat VPS: ganti `wireguard-go` userspace dengan solusi yang bisa load banyak peer (kernel module tidak bisa di OpenVZ; opsi: per-peer apply via `wg-apply-peers.py` yang sudah disiapkan, atau naikkan di node dengan kernel WG support).
- Kembalikan / buat script startup yang valid & enable-kan unit-nya.
- Amankan permission file `/etc/wireguard/*` menjadi `600` root-only.
- Tambahkan route + allowed-ips `192.168.10.0/24` jika LAN #2 harus reachable.
