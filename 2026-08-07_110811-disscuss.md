Ini ringkasan diskusinya — saya sudah diagnosa read-only, dan ada 3 temuan. Yang pertama sudah terbukti sebagai penyebab "user tidak bisa konek internet":

TEMUAN 1 — DNS router mati total (akar masalah utama)
  Router pakai DoH (cloudflare-dns.com via TCP 443), tapi firewall output chain cuma izinkan UDP 53, UDP 123, icmp, lalu DROP semua. Jadi koneksi DoH keluar DIBUANG, resolver macet, client timeout.
  Bukti tes dari host (simulasi client LAN via source 192.168.10.1):
    dig @1.1.1.1 google.com          -> OK (internet host sehat)
    dig @192.168.18.12 google.com    -> timeout (wajar, firewall input benar)
    dig -b 192.168.10.1 @192.168.18.12 google.com -> TIMEOUT  <- DNS router tidak menjawab
  Client dapat IP dari DHCP, tapi query DNS tidak pernah dijawab -> browser gagal semua.

TEMUAN 2 — IP conflict: host Proxmox juga pakai 192.168.10.1
  vmbr1 host = 192.168.10.1, padahal itu IP LAN router (ether2). Dua perangkat satu IP di segmen yang sama -> ARP rebutan -> gateway client "kadang nyambung kadang tidak". Ini penjelas kenapa masalah terasa intermiten, dan bisa ikut mengganggu TP-Link.

TEMUAN 3 — WiFi TP-Link signal 0
  Setup AP mode + DHCP off sudah benar. Signal drop ke 0 itu masalah sisi radio AP: auto channel nabrak SSID admin Huawei, firmware, atau power/PoE. Perlu sentuhan di web UI AP (192.168.10.2), nggak bisa 100% dari server — tapi bisa dibantu (channel tetap, reservation IP, dll).

Usulan perbaikan (urutan prioritas):
  1. Fix DNS: matikan DoH, pakai 1.1.1.1/8.8.8.8 UDP + izinkan TCP 53 keluar (opsi A, saya rekomendasikan — sederhana dan sedikit failure mode). Alternatif B: pertahankan DoH tapi buka TCP 443 keluar + pastikan NTP.
  2. Ganti IP vmbr1 host ke 192.168.10.250 (di luar pool DHCP).
  3. DHCP reservation buat AP di 192.168.10.2 + panduan stabilisasi WiFi (channel tetap non-overlap, firmware, power).
  4. Verifikasi end-to-end dari client LAN + update hasil di repo.
