## 1. Ringkasan Eksekusi

**Masalah:** Error 502 Bad Gateway saat SOAP GetInfoRequest dari browser ke `mail.ciptamasjaya.co.id/service/soap/`. Error 404 pada `/services/chats/license`.

**Konfirmasi Root Cause (Sesuai Analisis Analyst dengan Koreksi):**
- **502 disebabkan nginx upstream pointing ke VPS public IP (103.56.149.231:8080), bukan localhost**
- Nginx Carbonio connect ke dirinya sendiri → loop → 502
- Error "Unsupported class file major version 65" ada di log zmmailboxd.out tapi **tidak menyebabkan 502** (red herring)
- **Path request Analyst SALAH:** bukan ke `127.78.0.7:10000`, tapi ke nginx Carbonio (:443) → upstream `zimbra_webclient` (:8080)

**Tindakan:**
1. Matikan `carbonio-configd` (prevent overwrite)
2. Edit `nginx.conf.web.upstreams` → ganti `mail.ciptamasjaya.co.id` → `127.0.0.1`
3. Edit `nginx.conf.zmlookup` → ganti `103.56.149.231` → `127.0.0.1`
4. Restart `carbonio-proxy-sidecar` (tidak refresh nginx process)
5. **Kill & restart nginx process** agar load config baru

## 6. Penjelasan Error SOAP 422 Saat Ini

**Status setelah fix:** SOAP endpoint **berhasil dijangkau** (tidak 502 lagi).

**Error yang muncul:**
```
<soap:Fault>
  <soap:Text>unknown document: GetInfoRequest</soap:Text>
</soap:Fault>
```

**Artinya:** Endpoint `/service/soap/` menerima request dan merespons (bukan 502), tapi document `GetInfoRequest` tidak dikenal oleh SOAP servlet saat ini.

**Kemungkinan penyebab:**
1. SOAP document namespace mismatch
2. Endpoint memerlukan auth token yang valid
3. Document `GetInfoRequest` mungkin deprecated atau perlu endpoint berbeda

**Ini bukan masalah sistem — ini masalah request format/auth.** Backend berfungsi.

## 7. About Error "Unsupported class file major version 65"

**Fakta yang diverifikasi:**
- Java version: OpenJDK 21.0.10 (Build-Jdk-Spec: 21 di semua JAR Carbonio)
- Error muncul di `/opt/zextras/log/zmmailboxd.out.202608170000` dalam konteks Guice dependency injection
- **Tidak ada JAR yang dikompilasi dengan Java 22+** — semua Build-Jdk-Spec: 21

**Kesimpulan:** Error ini kemungkinan:
1. Red herring — error log yang tidak mengganggu request path
2. Atau proses lama yang crash dan restart (log stale)
3. Atau masalah loading library tertentu

**Tidak perlu tindakan yang berkaitan dengan Java version mismatch.**
